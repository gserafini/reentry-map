## Conditional attack chains

- **Retained privileged JWT → bulk user listing → password hashes → possible offline password guessing.** Baseline authorization/listing transitions were supported by source. Hash recovery or subsequent account compromise was not attempted. Current role checks and response projections break the chain. ATT&CK context: **T1078** (Valid Accounts); **T1110.002** (Password Cracking) only for the hypothetical subsequent guessing step.
- **Anonymous batch → enabled verification → attacker-selected URL/redirect/subresource → potential internal service request or workload amplification.** The unsafe request path existed; internal service exploitation, cloud credential retrieval, exfiltration, and RCE were not demonstrated. Trusted verification plus numeric public-only egress breaks these transitions. ATT&CK context: **T1190** (Exploit Public-Facing Application), with **T1499** (Endpoint Denial of Service) as a conditional availability outcome.
- **Forged public fields → moderation/provenance or analytics corruption.** The affected records were suggestions and analytics, not authenticated login sessions. Server ownership/status/identity assignment prevents the demonstrated field-control paths. ATT&CK context: **T1565.001** (Stored Data Manipulation).

ATT&CK mappings describe applicable behavior or conditional follow-on activity; they do not assert that an intrusion occurred.

## Outbound boundary review and durable corrections

[public-network.mjs](../../lib/utils/public-network.mjs) rejects unsupported schemes, credentials in URLs, nonstandard ports, private/reserved destinations, mixed DNS answers, mapped/compatible IPv4, NAT64 special ranges, Teredo, and 6to4. Native requests pin the validated answer to the actual socket lookup, verify TLS, avoid pooled connections, check every redirect, and strip credential/cookie forwarding.

Native fetch limits include 20 active requests per process, a deadline including DNS/redirects, five redirects, and 2 MiB limits on both wire and decoded body. Decoder failures, aborts, and oversized gzip/Brotli outputs destroy decoder/response/request state. Fresh sandboxed browser contexts use a short-lived CONNECT proxy with numeric destination pinning, loopback bypass suppression, disabled non-proxied WebRTC UDP, blocked service workers/downloads, two browser slots, and socket/traffic/lifetime budgets. HTTPS wire limits do **not** cap decoded browser content, DOM, images, or JavaScript memory; I038 covers OS-level limits.

Independent review found an HTTP-status handling crash: an upstream status outside the Web `Response` range threw from an asynchronous event handler. A focused status-600 regression reproduced it before repair; response construction now rejects through cleanup. Review also found missing decoder destruction, now covered by gzip/Brotli overflow, upstream abort, and corrupt-stream regressions. Proxy tests verify unsafe CONNECT rejection, numeric pinning, private DNS rejection, and idempotent shutdown.

Parent-run controlled browser acceptance reported public native/browser **200**, private navigation **403**, blocked private image subresources, and **zero connections** to the private fixture. The reviewer inspected the acceptance fixture and regression tests. This evidence covers tested Chromium/proxy behavior and does not constitute arbitrary production exploitation.

## Open decisions and limitations

- **B080:** private-signup/access design remains a separate product/security decision.
- **B058:** guarded comparison identified shared staging/production secrets; environment separation and rotation remain blocked on owner authorization. No values are included here and no credentials were changed by this review.
- **I037:** nonce/hash CSP migration remains open; current inline/eval allowances reduce defense in depth.
- **I038:** enforce browser CPU/memory/process limits at the OS boundary. Proxy wire/time/concurrency limits do not provide decoded-renderer memory isolation.
- **I039:** shared durable quotas, aggregate work budgets, and hard intake byte limits remain. Process-local counters reset on restart and multiply across workers. Input schemas validate after JSON parsing. Forwarded-address trust additionally depends on Apache appending the actual peer and preventing untrusted direct upstream access.

Available CLI tooling included npm audit and Git. Gitleaks, Snyk, Semgrep, and Trivy were unavailable; a comprehensive independent secret-history scan and dedicated SAST/container scan were not performed. No production data modification, brute force, DoS, real-user impersonation, or production exploit testing was performed. Database behavior was reviewed through source and isolated regression tests rather than live exploit queries. A clean package audit does not prove absence of vulnerabilities or malicious code.
